# AGENTS.md

Это материал курса «Непрерывная интеграция (CI)», а не приложение. Студент
форкает репозиторий и пишет воркфлоу сам. Поэтому две вещи, которые снаружи
читаются как недоделки, здесь намеренные, и чинить их не надо.

## Каркас в `main`

`.github/workflows/main.yml` — каркас. Между `# BEGIN` и `# END` пусто, потому
что там пишет студент по шагам самостоятельных работ. Регион остаётся пустым;
правка внутри маркеров сначала обсуждается с человеком.

Отсюда следствие: `main` живёт без настоящей проверки. Воркфлоу зелёный, но
`lint` и `test` не запускаются, и PR сборкой не проверяются. Это осознанная
плата за целостность самостоятельной, разобрана в #42. Второй рабочий воркфлоу
под другим именем её не снимает: форк снова приезжает с готовым CI.

Имя файла `main.yml` фиксировано — по этому пути курс ссылается на эталон.

## Эталон в `final`

`final` это тот же файл с заполненным регионом плюс бейдж в README. На него
курс показывает студенту как на ответ.

Ветка держится как `main` плюс один коммит, без собственной истории. Обновляют
её пересборкой:

```sh
git rebase origin/main <ветка с эталонным коммитом>
git branch -f final <ветка с эталонным коммитом>
git push --force-with-lease origin final
```

Сверка после: `gh api "repos/hexlet-components/hexlet-ci-app/compare/main...final"`
даёт `ahead 1`, `behind 0` и ровно два файла.

Бейдж в README ветки `final` несёт `?branch=final`: без параметра GitHub
показывает статус дефолтной ветки, то есть каркаса. В README ветки `main`
бейджа нет — его добавление входит в самостоятельную.

Версия Node в воркфлоу берётся из `engines` в `package.json`.
